## Implementing the Light Function 
The control of the lights comes from the control node depicted as 'Relationships & Lights' in the diagram below. \

<img src="https://github.com/user-attachments/assets/b0aa70e3-0a2a-4f85-8dae-bd0c57ed2926" width="400"/> 

From the diagram you can see that the control node works by assigning a colour depending on what drone it is, who it's following and the follower number. This is defined in a relationship matrix as seen below: 

``` python 
self.relationship_matrix = np.array([[1, 0, 0], [2, 1, 1], [3, 1, 2]])
```
The indices have the following meanings:
1. The index of the drone
2. The index of the leader (0 means that the drone has no leader/is not following any drones)
3. The number of the drone in the follower sequence (0 means that the drone has no leader)

After specifying the relationship matrix, a custom publisher is created to relay info from the control node to the actual drone nodes. The creation of this topic is covered separately in "Creation of a Custom Topic" section of this wiki.

Among other information, this publisher informs the drones of the colour of their light according to the leader - follower configuration they are meant to represent. For the 3-drone case, this is done in a very crude manner:
```python
if matrix[0][2] != matrix[1][2] and matrix[0][2] != matrix[2][2] \
   and matrix[1][2] != matrix[2][2]:
   seq_colours = ['purple', 'amber', 'amber']
else:
   seq_colours = ['cyan', 'green', 'red']
```

These colour name strings can later be used to call the correct functions for the actual light control from a dictionary. The colour arrangement is then used to specify the light colour for every drone, specifically, using the relationship matrix once more:

```python
msg.light_colour = seq_colours[matrix[drone_index][2]]
```

where msg represents the topic the parameters are published to. For drone 1, this would be:

```python
MsgClass = Drone1Info()
msg = MsgClass  
```

Once the specified light color has reached the drone by subscribing to the custom topic, the function light_control is used to put the light into use on the drone. The forwarded light colour is used to obtain a colour from the following dictionary:

```python
color_dict = {
   "off": LedControl.COLOR_OFF,
   "red": LedControl.COLOR_RED,
   "green": LedControl.COLOR_GREEN,
   "blue": LedControl.COLOR_BLUE,
   "yellow": LedControl.COLOR_YELLOW,
   "purple": LedControl.COLOR_PURPLE,
   "amber": LedControl.COLOR_AMBER,
   "cyan": LedControl.COLOR_CYAN,
   "white": LedControl.COLOR_WHITE,
   }
```
Moreover, a light function mode is specified from the mode dictionary. This, however, is always set to "on" for the ease of actually seeing it onboard the drone in the simulation.

```python
mode_dict = {
    "off": LedControl.MODE_OFF,
    "on": LedControl.MODE_ON,
    "disabled": LedControl.MODE_DISABLED,
    "blink_slow": LedControl.MODE_BLINK_SLOW,
    "blink_normal": LedControl.MODE_BLINK_NORMAL,
    "blink_fast": LedControl.MODE_BLINK_FAST,
    "breathe": LedControl.MODE_BREATHE,
    "flash": LedControl.MODE_FLASH,
        }
```

The code to do this automatically is the following:

```python
msg = LedControl()
msg.led_mask = 0xff # All LEDs
msg.mode = mode_dict[funct]
msg.color = color_dict[colour]
```

Here LedControl() represents the px4 uORB message of the light functionality, which is tied to the light control publisher.

And finally, in order to let the user know that the light control has turned the light on, the following message is printed (only once):

```python
# Log the light control command only if the colour has changed
        if msg.color != self.colour_current:
            self.get_logger().info("Light control command sent")
            self.light_logged = True
        
        else:
            pass
        
        # Update the current colour
        # This is to avoid logging the same colour change multiple times
        self.colour_current = msg.color
```
