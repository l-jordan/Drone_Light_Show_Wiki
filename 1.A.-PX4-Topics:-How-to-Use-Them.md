PX4 is an open source flight control software for drones. It also has compatibility with ROS2, the robotics software used to interface with the drone. To use PX4 and ROS2 together, it is important to understand what topics are available and how they work. 

It is first recommended that you read the README.md file so you understand how the PX4-ROS2 MICRO-XCRE DDS bridge works. 

The two sources of documentation are the topics that can be used in the ROS2 node and the uORB messages and how they work: 
1. [ROS2 Topics](https://github.com/PX4/PX4-Autopilot/blob/main/src/modules/uxrce_dds_client/dds_topics.yaml) 
2. [uORB Messages](https://docs.px4.io/main/en/msg_docs/) (The topics are usually mentioned at the bottom of the file but it can be easier to use source  [[1]](https://github.com/PX4/PX4-Autopilot/blob/main/src/modules/uxrce_dds_client/dds_topics.yaml) as a quick 'dictionary')

The uORB messages are written in a very similar, if not the same, format as an older messaging protocol for communicating with drones called [MAVLink](https://mavlink.io/en/). The uORB messages tell us what parameters can be changed to execute the desired function when we publish to a topic. In this documentation, we will show you how to use the topics in general but also specific examples of some of the topics and uORB messages we used to establish communication between drones and to achieve the desired drone function in our offboard_control.py example.

## General Instructions 

1. Determine if you want to subscribe or publish to a topic
2. Determine what parameters you need to subscribe/publish to by referring to the documentation [[2]](https://docs.px4.io/main/en/msg_docs/)
3. In your Python file, import the uORB messages associated with the topics you want to use from px4_msgs.msg as seen below:
``` python 
from px4_msgs.msg import <Insert uORB message>
```
4. Create your subscriber or publish under def __init__. 
 A subscriber and publisher need the following information: the uORB name, the topic name, the QoS profile and for subscribers only, the corresponding function that can print/define the subscriber information. 

``` python 
def __init__(self) -> None:
        super().__init__('offboard_control_node')

        # Configure QoS profile for publishing and subscribing
        qos_profile = QoSProfile(
            reliability=ReliabilityPolicy.BEST_EFFORT,
            durability=DurabilityPolicy.TRANSIENT_LOCAL,
            history=HistoryPolicy.KEEP_LAST,
            depth=1
        )
                
        # Create subscribers
        self.subscriber = self.create_subscription(
            <uORB message name>, '/fmu/out/<topic_name>', self.<subscriber_function>, qos_profile)

        # Create publishers
        self.publisher = self.create_publisher(
            <uORB message name>, '/fmu/out/<topic_name>', qos_profile)

```
5. (SUBSCRIBER ONLY) Create the definition used to access the topic information. To know what parameters you want to access, visit the second source to see what parameters are associated with the uORB message associated with the topic you are subscribing to [[2]](https://docs.px4.io/main/en/msg_docs/).

```python
def subscriber_function(self, msg):
    # Example
    x = msg.x 
    y = msg.y
    z = msg.z

    # Print the message outputs 
    self.get_logger().info(f"x = {x}, y = {y}, z = {z}")
```
6. (PUBLISHER ONLY) Create the definition used to publish information to the desired parameters. To know what parameters you need to access, visit the second source to see what parameters are associated with the uORB message with the topic you are publishing to [[2]](https://docs.px4.io/main/en/msg_docs/).

```python
def publisher_function(self, x: float, y: float, z: float):
    msg = <Insert uORB message>
    # Example
    msg.<param_name1> = x 
    msg.<param_name1> = y
    msg.<param_name1> = z
   
    # The name of the publisher you defined in __init__ for your uORB message
    self.publisher.publish(msg)

```

## Subscriber Example
For this example, I will be showing you how to access the GPS information of the drone. 

To access this information you have to use the uORB message: [**SensorGps**](https://docs.px4.io/main/en/msg_docs/SensorGps.html) \
This is associated with the topic: `/fmu/out/vehicle_gps_position` 

I urge you to look at the documentation related to the SensorGps uORB message to see how these messages are usually formatted. We will use the following extract of the file to access the GPS coordinates of the drone:

``` C
float64 latitude_deg		# Latitude in degrees, allows centimeter level RTK precision
float64 longitude_deg		# Longitude in degrees, allows centimeter level RTK precision
float64 altitude_msl_m		# Altitude above MSL, meters
```

With this information, the subscriber can be built. 

1. Following the aforementioned steps, import the uORB message from px4_msgs.msg as `from px4_msgs.msg import SensorGps`.

2. In the __init__ definition, define the subscriber. In this example, we will use the a function called `gps_position_callback` to access the contents of the SensorGps topic.
``` python
def __init__(self) -> None:
        super().__init__('offboard_control_node')

        # Configure QoS profile for publishing and subscribing
        qos_profile = QoSProfile(
            reliability=ReliabilityPolicy.BEST_EFFORT,
            durability=DurabilityPolicy.TRANSIENT_LOCAL,
            history=HistoryPolicy.KEEP_LAST,
            depth=1
        )
                
        # Create subscribers
        self.subscriber = self.create_subscription(
            SensorGps, '/fmu/out/vehicle_gps_position', self.gps_position_callback, qos_profile)
```
3. Create the gps_position_callback. Within this definition, we want to access the **latitude_deg**, **longitude_deg** and **altitude_msl_m** data. By following the format shown in step 5 in the previous section, this can be done in the following way: 

``` python
    def gps_position_callback(self, msg):
        # Print GPS position data
        lat = msg.latitude_deg
        lon = msg.longitude_deg
        alt = msg.altitude_msl_m
        self.get_logger().info(f'Lat: {lat:.6f}, Lon: {lon:.6f}, Alt (MSL): {alt:.2f} m')
```
4. Launch the node and monitor the terminal. You should see an output similar to this (depending on your trajectory):

``` python
[offboard_control_node-1] [INFO] [1746907973.417738788] [control]: Lat: 47.397959, Lon: 8.546141, Alt (MSL): 0.22 m
[offboard_control_node-1] [INFO] [1746907973.555814720] [control]: Lat: 47.397959, Lon: 8.546141, Alt (MSL): 0.20 m
[offboard_control_node-1] [INFO] [1746907973.671510204] [control]: Lat: 47.397959, Lon: 8.546142, Alt (MSL): 0.22 m
[offboard_control_node-1] [INFO] [1746907973.733416409] [control]: Lat: 47.397959, Lon: 8.546142, Alt (MSL): 0.21 m
```

## Publisher Example
For this example, we will show you how to send the initial Offboard Control Mode command. 

To access this information you have to use the uORB message: [**OffboardControlMode**](https://docs.px4.io/main/en/msg_docs/OffboardControlMode.html) \
This is associated with the topic: `px4_msgs::msg::OffboardControlMode` \

I urge you to look at the documentation related to the OffboardControlMode uORB message to see how these messages are usually formatted. We will use the following extract of the file to access the relevant parameters of the drone:

``` C
int64 timestamp		# time since system start (microseconds)

bool position
bool velocity
bool acceleration
bool attitude
bool body_rate
```

1. Following the aforementioned steps, import the uORB message from px4_msgs.msg as `from px4_msgs.msg import OffboardControlMode`.

2. In the __init__ definition, define the publisher. 

``` python
self.offboard_control_mode_publisher = self.create_publisher(OffboardControlMode, '/fmu/in/offboard_control_mode', qos_profile)
```

3. Create a new definition specifically for sending the offboard command message to the drone. In this example, we are stating that we will using only position setpoints to control the drone. Therefore, the parameters should be updated accordingly. 

```python 
    def publish_offboard_control_heartbeat_signal(self):
        msg = OffboardControlMode()
        msg.position = True
        msg.velocity = False
        msg.acceleration = False
        msg.attitude = False
        msg.body_rate = False
        msg.timestamp = int(self.get_clock().now().nanoseconds / 1000)
        self.offboard_control_mode_publisher.publish(msg)
```

4. In your main control loop, specify that you want to publish offboard control mode messages to OffboardControlMode() like so:

``` python
def control_loop(self) -> None:
        self.publish_offboard_control_heartbeat_signal()
``` 

In the __init__ statement, the control loop can be run by stating the frequency you want the control loop to update in the following way: 

``` python
self.timer = self.create_timer(0.1, self.control_loop)
``` 

* Please keep in mind, by publishing the Offboard Mode to the uORB message OffboardControlMode() doesn't mean that the drone will change into offboard mode. To do this, you need to continuously publish this message to OffboardControlMode(). Then you need to send setpoints for at least 1 second before you can engage in offboard mode by sending an offboard mode command to the [VehicleCommand](https://docs.px4.io/main/en/msg_docs/VehicleCommand.html) uORB message. (MAVLink documentation regarding [VEHICLE_CMD_DO_SET_MODE](https://mavlink.io/en/messages/common.html#MAV_CMD_DO_SET_MODE) is needed). More information, including an example, can be found on this [page](https://github.com/p4mars/drone_light_show/wiki/Setting-up-the-Offboard-Control-of-the-Drone).

## Using VehicleCommand
The (VehicleCommand)[https://docs.px4.io/main/en/msg_docs/VehicleCommand.html] uORB topic is very frequently used and also requires many parameters to be set in order for it to carry out the desired command. 

The VehicleCommand uORB message allows you to send commands to carry out functions such as arming and disarming, automatic landing & take-off, etc. 

In this example, I will show you how to arm, disarm and land using one generic definition for the VehicleCommand publisher and separate definitions for each of these actions. 

**1. Creating the generic VehicleCommand definition** \
Looking at the bottom of the [documentation](https://docs.px4.io/main/en/msg_docs/VehicleCommand.html), there are seven parameters that can be updated depending on what action you want to carry out. There are four separate parameters that need to be set regarding the target & source system and metadata every time a command is sent. These are: 

* `target_system` - Which drone to send the command to. This is set to 1 for now. 
* `target_component` - Which component on the drone should handle the command. This is set to 1 for autopilot.
* `source_system` - Which system (e.g., GCS or companion computer) sent the command. This is 1 for companion computer.
* `source_component`- Which module (e.g., ROS 2 node) sent the command
* `from_external `- Indicates if the command came from an external source (e.g., ROS 2). This is always set to True for offboard mode

Otherwise this definition is written as per the previous example where it send the command to the publisher. 

``` python
def publish_vehicle_command(self, command, **params) -> None:
        msg = VehicleCommand()
        msg.command = command
        msg.param1 = params.get("param1", 0.0)
        msg.param2 = params.get("param2", 0.0)
        msg.param3 = params.get("param3", 0.0)
        msg.param4 = params.get("param4", 0.0)
        msg.param5 = params.get("param5", 0.0)
        msg.param6 = params.get("param6", 0.0)
        msg.param7 = params.get("param7", 0.0)
        msg.target_system = 1
        msg.target_component = 1
        msg.source_system = 1
        msg.source_component = 1
        msg.from_external = True
        msg.timestamp = int(self.get_clock().now().nanoseconds / 1000)
        self.vehicle_command_publisher.publish(msg)
``` 
As seen above, the parameters can be unpacked, so it is easy to only set the relevant parameters needed for your specific control. 

**2. Creating the Arming and Disarm Command** \
In the [VehicleCommand documentation](https://docs.px4.io/main/en/msg_docs/VehicleCommand.html), it states what parameter needs to be changed to change to offboard mode and what command name you should use to do this. This can be seen below:

```
# used as param1 in ARM_DISARM command
int8 ARMING_ACTION_DISARM = 0
int8 ARMING_ACTION_ARM = 1

``` 
Therefore, to create the arming and disarming commands, you create an arm and a disarm definition, call the `publish_vehicle_command(self, command, **params)` using the command name `ARMING_ACTION_ARM/ARMING_ACTION_DISARM` and setting the parameter 1 to 1 or 0. An example of this is seen below:

```python 
    # Arming the vehicle by sending the command
    def arm(self):
        self.publish_vehicle_command(
            VehicleCommand.VEHICLE_CMD_COMPONENT_ARM_DISARM, param1=1.0)
        self.get_logger().info('Arm command sent')

    # Disarming the vehicle by sending the command
    def disarm(self):
        # Calling the publish_vehicle_command() definition
        self.publish_vehicle_command(
            VehicleCommand.VEHICLE_CMD_COMPONENT_ARM_DISARM, param1=0.0)
        self.get_logger().info('Disarm command sent')
```
Then as you would with any topic publisher, you call this definition within your control loop to arm or disarm your drone.

``` python
def control_loop(self) -> None:
        ...
        # Please note that the drone will not arm unless offboard control requests and trajectory setpoints have been sent BEFORE
        # sending the command to go into offboard mode
        self.arm()
        self.disarm()
        ..
``` 

**3. Creating the Landing Command** \
Serving as an extra example, this will show you how to automatically land. Note that the drone must have been armed and must of taken off before this can be used. In the [VehicleCommand documentation](https://docs.px4.io/main/en/msg_docs/VehicleCommand.html), the following can be said about landing:

```
uint16 VEHICLE_CMD_NAV_LAND = 21			# Land at location |Empty| Empty| Empty| Desired yaw angle.| Latitude| Longitude| Altitude|
``` 
The parameters are given to the right in the comment. It is also possible to send the command without specifying the latitude, longitude and altitude so it will land in its current position. The example below shows how you can alter specific parameters such as parameters 5, 6 and 7 representing latitude, longitude and altitude with the parameter names as placeholders. 

```python 
    def land(self):
        self.publish_vehicle_command(VehicleCommand.VEHICLE_CMD_NAV_LAND, param5 = <Latitude>, param6 = <Longitude>, param7 = <Altitude>)
        self.get_logger().info("Switching to land mode")
```
