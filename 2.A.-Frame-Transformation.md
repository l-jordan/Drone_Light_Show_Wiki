This section defines the use of the follower frame transform. The goal of this transform is to calculate the shift in the drones' local coordinate frames (since all drones have their local frame, centred at their initialised position - the location where the drone is spawned). 

The frame transform is rather simple in theory: 
 1) Take the local frame reference coordinates (the local frame origin location in the global frame) of the leader and follower drones.
 2) Calculate the difference between the origin points in all 3 axes (NED: north, east, down).


Let's look at the code in action:
The function takes 2 inputs: the name of the leader drone and the number of the follower drone. This allows for a parametric expansion to an unlimited amount of follower drones (at least in theory).

Then, the reference latitude and longitude (in degrees) locations of the leader and follower drone are taken by using the vehicle_local_position attributes ref_lat and ref_lon respectively. [See the official documentation for all of the available attributes: https://docs.px4.io/main/en/msg_docs/VehicleLocalPosition.html]

```powershell
def follower_frame_transform(self, vehicle_leader, follower_number):
        leader_latitude_origin = vehicle_leader.vehicle_local_position.ref_lat
        leader_longitude_origin = vehicle_leader.vehicle_local_position.ref_lon
        #Leader_altitude = vehicle_leader.global_pos.alt

        follower_latitude_origin = self.vehicles[follower_number].vehicle_local_position.ref_lat
        follower_longitude_origin = self.vehicles[follower_number].vehicle_local_position.ref_lon
```

Then, the coordinates are converted to meters as per the WGS84 World Geodetic System model. This works out favourably for us, as the local frames also use meters as their base unit. The conversion is done by the following definition:

```powershell
        def convert_coordinate_to_meters(latitude, longitude):
            #### This converts the coordinate degrees to meters as per wikipedia WGS84 conversions 
            # (accurate to a magnitude of cm)
            latitude = np.deg2rad(latitude)
            longitude = np.deg2rad(longitude)
            # Conversion according to the WGS84 ellipsoid model
            # https://en.wikipedia.org/wiki/Geographic_coordinate_system#Latitude_and_longitude
            m_latitude_per_deg = 111132.92 - 559.82*np.cos(2*latitude) + 1.175*np.cos(4*latitude) - 0.0023*np.cos(6*latitude)
            m_longitude_per_deg = 111412.84*np.cos(latitude) - 93.5*np.cos(3*latitude) + 0.118*np.cos(5*latitude)
            m_latitude = np.rad2deg(latitude) * m_latitude_per_deg
            m_longitude = np.rad2deg(longitude) * m_longitude_per_deg
            return m_latitude, m_longitude
```
Using this conversion, the difference in the origin locations are found for the latitude and longitude:

```powershell
    leader_latitude, leader_longitude = convert_coordinate_to_meters(leader_latitude_origin, leader_longitude_origin) 
    follower_latitude, follower_longitude = convert_coordinate_to_meters(follower_latitude_origin, follower_longitude_origin)
    #calculate the difference in follower coordinates wrt the leader 
    # This is the follower position in the leader local frame
    origin_delta_latitude = follower_latitude - leader_latitude
    origin_delta_longitude = follower_longitude - leader_longitude
```

And finally, the coordinate transform is logged (to be double-checked by the person running the simulation) and added to the attribute "coordinate transform" of the respective follower drone:

```powershell
   self.get_logger().info(f"coordinate transform for follower {follower_number}: {[origin_delta_latitude, origin_delta_longitude]}") #, delta_altitude]}")
   self.vehicles[follower_number].coordinate_transform = [origin_delta_latitude, origin_delta_longitude]
```

A tentative reader might have noticed that the "down" direction of the coordinate is omitted from the described transformation. This is done due to the fact that all of the drones are going to be initialised at the 0-altitude. As such, calculating the difference of the frames in the down direction would only increase the computational load of the simulation, whilst it is known that the result is always 0 (unless an error is introduced due to truncation of numerical values for example). This functionality should, however, be added to the code if the drones were to be initialised at differing altitudes such as in rough terrain, or perhaps on a specifically designed launch structure, like a pedestal. This would also be needed if the drones were to fly in real life and not just in a simulation.
