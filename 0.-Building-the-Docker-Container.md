To build the Docker container, both a DockerFile and devcontainer.json file is needed. Both of these should be stored in a folder called .devcontainer in the desired location on your laptop. These two files are needed to create the development container. The DockerFile builds the environment (OS + tools + ROS + PX4) and the devcontainer.json file configures VS Code to connect to and use that environment.

## Why do we do this?
Creating a development container will allow anyone to access the same versions of software (such as ROS2 and Gazebo), same libraries (numpy, scipy, etc.) and all other external downloads needed (PX4 installations, Micro XCRE-DDS bridge, etc.) for a specific development project or overall to run an already existing simulation. It prevents each contributor from having incompatible or different versions of software and libraries so that everyone is working with the same tools. Then by building and opening in the container, the developer can use everything again as normal but without the stress of worrying about incompatibilities and about downloading specific packages/software that would be needed. 

In this specific project, we will need to ensure that everyone is working with Gazebo Ignition and ROS2 Humble. Additionally, all python libraries that would need to be used will be included along with all necessary downloads from the PX4 side, such as PX4 itself, the required drone models needed for Software-In-The-Loop (SITL) simulations and the Micro XCRE-DDS bridge to communicate between the drone and ROS2. 

This page will show you how to construct your DockerFile and devcontainer.json file for this specific application. After this, you can modify it anyway you like for your own specific project!

## Creating the DockerFile
To understand the basic configuration of a DockerFile, please watch this video before proceeding: \

### Base Setup: User and Workspace
This base setup starts us from an official ROS 2 Humble desktop image. ARG lets you switch ROS versions easily.

```dockerfile
ARG ROS_DISTRO=humble 
FROM osrf/ros:${ROS_DISTRO}-desktop AS ros_user_setup
```
### Creating a Non-Root User
Creating a root user would allow anyone to do anything on the system, including installing software, changing system files, or deleting everything (even by accident). The non-root user has limited permissions. It can run programs, edit files in their own space, but can't mess with system-critical stuff without sudo. Therefore, for security, a non-root user is created. 

```dockerfile
ARG ROS_USER=ros
ARG ROS_USER_UID=1000
ARG ROS_USER_GID=$ROS_USER_UID

```

After this step, the user is added to the system, installs sudo so the new-user can have admin tasks and sets it up to be passwordless for easy access.

```dockerfile
RUN groupadd --gid $ROS_USER_GID $ROS_USER \
    && useradd -s /bin/bash --uid $ROS_USER_UID --gid $ROS_USER_GID -m $ROS_USER \
    && apt-get update \
    && apt-get install -y --no-install-recommends sudo \
    && echo $ROS_USER ALL=\(root\) NOPASSWD:ALL > /etc/sudoers.d/$ROS_USER \
    && chmod 0440 /etc/sudoers.d/$ROS_USER 
```
The last step is to switch to this new user and make the ROS2 workspace.

```dockerfile
USER $ROS_USER
RUN mkdir -p /home/ros/ros2_ws/src
```
### Development Stage: Tools & Dependencies
This stage will start from the previous ROS image and built on it in a stage called the `dev` stage. It will stack the layers like LEGOs. 

First, start from the previous image like so:
```dockerfile
FROM ros_user_setup AS dev
```

What it will install are:
1. Build tools (e.g., build-essential, cmake)
2. Dev utilities (e.g., htop, vim, wget, ccache)
3. ROS-specific tools (e.g., colcon, rosdep)
4. Clean up after to keep the image light

This can be written as so:
```dockerfile
RUN sudo apt-get update && sudo apt-get install ...
```
Please refer to lines 29-54 to see what our installations are.

To add Python-based linters and formatters like `flake8`, `black`, `isort`, use:

```dockerfile
RUN sudo pip3 install ...
```

This can be seen from lines 57-63. 

To fix issues with numpy binary compatibility:
```dockerfile
RUN sudo pip3 install --no-cache --upgrade numpy
```

Lastly, to update ROS dependency database:

```dockerfile
RUN rosdep update
```

### Installing the Micro XCRE-DDS Agent
Clones and builds the Micro-XRCE-DDS Agent, which bridges the drone's controller software to ROS2. 

```dockerfile
WORKDIR /home/ros
RUN git clone -b v2.4.2 https://github.com/eProsima/Fast-DDS.git \
    && cd Fast-DDS \
    && git clone https://github.com/eProsima/Micro-XRCE-DDS-Agent.git \
    && cd Micro-XRCE-DDS-Agent \
    && mkdir build && cd build \
    && cmake .. \
    && make -j$(nproc) \
    && sudo make install \
    && sudo ldconfig /usr/local/lib/
```

### Simulation Stage
Adding the simulation tools such as Gazebo, ROS2-Gazebo bridges and important ROS2 simulation packages. 

```dockerfile
FROM dev AS simulation
RUN sudo wget ... && sudo apt-get install gz-fortress ...
```

The full installation can be found from lines 85-103.

### PX4 Installation
In this step, all the dependencies needed for PX4 development are installed. These include numerical libraries, PX4 tools and Python packages:

```dockerfile
RUN sudo apt-get install ... && pip3 install pyulog ...
```
The full list is found from lines 108-134. 

Once these dependencies are installed, the PX4 autopilot repository and all its submodules can be cloned. Once that is completed, PX4's own setup script is run to configure everything and PX4 builds the Software-In-The-Loop simulation (SITL).

```dockerfile
WORKDIR /home/ros/PX4-Autopilot
RUN bash ./Tools/setup/ubuntu.sh

RUN make px4_sitl
```

### Final Touch 
This sets the default startup command when the container runs — gives you an interactive shell with ROS sourced under the working directory: `/home/ros/ros2_ws`.

```dockerfile
ENTRYPOINT ["/ros_entrypoint.sh"]
CMD ["/bin/bash"]
```
Now your DockerFile is complete.
