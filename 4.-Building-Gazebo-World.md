In this page, I will show you how to create a Gazebo world specifically for the purpose of using it for a PX4 SITL application like what is used in our final simulation.

## Understanding PX4-Autopilot Directory
When you use the command `make px4_sitl gz_x500`, it runs Gazebo using the x500 model under the Models directory as indicated by the directory diagram below. By default it will launch an empty or default world. 

<img src="https://github.com/user-attachments/assets/d9b4ecb5-bc98-4ca9-a051-dc9dbfcdf41c" width="400"/>

In the DockerFile, a special command was added that would map any Gazebo related development files created in the Gazebo_files folder in the ROS2 workspace to their appropriate locations in the `/home/ros/PX4-Autopilot` directory. This was done so the custom development files could be easily pushed to our Github repository. 

In the `Gazebo_files` folder, there is a TU Delft flame 3D model that is used in the simulation and the Gazebo world itself which has trees, a night sky and the TU Delft logo. Because of the DockerFile addition, mapping these files, this world is easily obtainable through the command `PX4_GZ_WORLD=sim_world make px4_sitl gz_x500`. 

In this page, it will outline how to create a model using the TU Delft flame example, how to build a world using online imports, custom models and how to modify the empty world and how to modify the DockerFile to ensure easy mapping. 

## Creating a Model 
As seen in the image above, there are three important files that are needed: the model.config, model.sdf and the .dae model itself. The .dae model needs to be exported from Blender/CATIA or some other 3D modelling tool with the correct dimensions, colours and initial alignment relative to your local frame. The most important thing to note are the colours that you used when creating your model as they are needed for your model.sdf file. 

### model.sdf file [[1]](https://classic.gazebosim.org/tutorials?tut=build_model#BuildingaModel)

Below is the `model.sdf `file which includes the relevant information about your model such as the mesh and material or all components that will be visualised. 

The first thing to do is to put in your model name exactly as it is for your .dae file. If you want to simulate physics you set `<static>false</static>`, otherwise you set it true and the model will stay static in the place you set it in your world file. For this model itself, it is put under <visual>, <geometry>, <mesh> so the mesh can be made from the .dae format and can be used in the world.

```bash
<sdf version="1.6">
  <model name="TU_Delft_logo">
    <static>true</static>
    <link name="link">
      <visual name="visual">
        <geometry>
         <mesh>
          <uri>model://TU_Delft_logo/TU_Delft_logo.dae</uri>
         </mesh>
        </geometry>
...
```
The colours used in the model are important and you have state them under the <material> section like seen below if you want them to appear on your model. They use normalised RGB numbers. You can also mess with some features such as making it glossy or matte through <specular> and being glowy or non-glowy through <emissive>. We used Deepseek to help us tweak these parameters. 

```bash
       ...
        <material>
          <ambient>0.0 0.18 0.38 1</ambient>  <!-- TU Delft blue (RGB: 0,46,98) -->
          <diffuse>0.0 0.18 0.38 1</diffuse>
          <specular>0.05 0.05 0.05 1</specular>  <!-- Matte finish -->
          <emissive>0 0 0 1</emissive>  <!-- Non-glowing -->
        </material>
      </visual>
    </link>
  </model>
</sdf>
```

By combining these two snippets together, you get your final `model.sdf` file!

### `model.config` [[1]](https://classic.gazebosim.org/tutorials?tut=build_model#BuildingaModel)
This file is to track the name and information about your model. You can also add information about the developer such as their name and email along with a description of the model. This is similar to a package.xml file for a ROS2 node. 

```config 
<model>
  <name>TU Delft Logo</name>
  <version>1.0</version>
  <sdf version="1.6">model.sdf</sdf>
  <author>
    <name>Your Name</name>
    <email>your@email.com</email>
  </author>
  <description>
    A custom model for PX4 Gazebo.
  </description>
</model>
```

These three files together create your model. 

## Creating a World 
The world is made through an .sdf file. To create this model, the [default.sdf](https://github.com/PX4/PX4-gazebo-models/blob/main/worlds/default.sdf) file created by PX4 was used as a template where elements were added and altered in order to create the sky and background along with importing models. 

### World Structure
The file is structured as an XML-based SDF (Simulation Description Format) file. The outermost tag defines a world, which contains all simulation settings, models, and environmental elements. Here you can see that Earth's gravity and magnetic field have been implemented. The ode engine is used for physics simulation, and the real-time settings ensure smooth simulation timing.

```sdf
<physics type="ode">
  <max_step_size>0.004</max_step_size>
  <real_time_factor>1.0</real_time_factor>
  <real_time_update_rate>250</real_time_update_rate>
</physics>
<gravity>0 0 -9.8</gravity>
<magnetic_field>6e-06 2.3e-05 -4.2e-05</magnetic_field>
<atmosphere type="adiabatic"/>
``` 

### Visuals & Lighting
The ambient and background colors have been modified to create a dark, moonlit environment. Lighting is also customized using a directional light source named sunUTC. This simulates soft, cool moonlight for a more dramatic nighttime setting to replicate a drone light show's operating conditions. 

```sdf
<scene>
  <grid>false</grid>
  <ambient>0.05 0.05 0.1 1</ambient>
  <background>0.01 0.01 0.03 1</background>
  <shadows>true</shadows>
</scene>

```

### Imported Models
Here the previously mentioned TU Delft flame model is implemented. The pine tree models are pulled directly from [Ignition Fuel](https://app.gazebosim.org/fuel). Multiple of these trees were added, renamed and given a different pose within the world.  
```sdf
<include>
  <uri>model://TU_Delft_logo</uri>
  <pose>12.5 4.5 0 0 0 0</pose>
</include>
...
<include>
  <uri>https://fuel.ignitionrobotics.org/1.0/OpenRobotics/models/Oak Tree</uri>
  <name>Pine Tree_1</name>
  <pose>15 -10 0 0 -0 0</pose>
</include>
```
### Terrain 
The ground is defined manually using the model block. This creates a large, textured ground plane with an earthy tone for visual realism. This was taken directly from the `default.sdf` file with altered colours. 
```sdf
<model name="ground_plane">
  <static>true</static>
  ...
  <visual name="visual">
    <geometry>
      <plane>
        <normal>0 0 1</normal>
        <size>500 500</size>
      </plane>
    </geometry>
    <material>
      <ambient>0.08 0.1 0.07 1</ambient>
      <diffuse>0.18 0.15 0.1 1</diffuse>
      <specular>0.01 0.01 0.01 1</specular>
    </material>
  </visual>
</model>

```
### Geolocation
To integrate real-world coordinates (e.g. for PX4 simulation), the world frame orientation was set along with its position in GPS coordinates. This is especially useful when simulating GPS data in conjunction with PX4 and ROS 2. Additionally, this can act as a base for tf tree generation. 

```
<spherical_coordinates>
  <surface_model>EARTH_WGS84</surface_model>
  <world_frame_orientation>ENU</world_frame_orientation>
  <latitude_deg>47.397971057728974</latitude_deg>
  <longitude_deg>8.546163739800146</longitude_deg>
  <elevation>0</elevation>
</spherical_coordinates>
```

## Updating the DockerFile
Since the PX4 Autopilot directory could not be directly altered as the changes would not sync with Github, a folder was created in the ros2_ws with the model and world files and were moved to their correct location upon opening the Docker container. 

To do this, the following lines were added to put these files in the correct locations. 
```DockerFile
RUN ln -s /home/ros/ros2_ws/Gazebo_files/sim_world.sdf /home/ros/PX4-Autopilot/Tools/simulation/gz/worlds/ && \
    ln -s /home/ros/ros2_ws/Gazebo_files/TU_Delft_logo /home/ros/PX4-Autopilot/Tools/simulation/gz/models/
```

Please be aware that some of these worlds such as baylands and forest are very detailed and can cause a lot of lag when running your simulation.
