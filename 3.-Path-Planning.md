This covers the initial path planning of the simulation for multiple drones under multiple nodes. The goal is to establish the flying protocol of the drones in leader and follower functions by utilising communication between the drones. 

The idea of the simulation is to display the TU Delft Prometheus' flame by having the drones follow a path along its edges. In order to do this, the path would have to be plotted as a sequence of points using some software. This was done in the photo editing software Gimp, using a path tool. The actual path of the drones can be seen in the figure below, with the sharper corners of the flame rounded out in order to aid the drones in moving a bit smoother in the actual simulation. 

![image](https://github.com/user-attachments/assets/e5a24099-399d-4633-b317-cf3def4cb615)

Moreover, having a bit of a separation between the in- and out-going "lanes" from the tip of the flame reduces the risk of collision between the drones if they happened to be in the same area of the flame at the same time for some unseen circumstance, as this would nominally not happen due to the set time separation between the drones along the same path.

Extracting the points from the above figure yielded the path for following the flame. However, some editing has to be performed for the flame to be followed as we want in a more intuitive manner:
1. The Gimp software uses the usual computer visual coordinate system where the x-axis points to the right, the y-axis points down and the origin is in the top-left corner of the picture. In order for the picture to be more intuitive (x-axis pointing to the right, y axis pointing up and the origin in the bottom-left corner, the points on the y-axis of the picture will have to be "flipped", done as follows:
```powershell
flame_points_y = np.max(flame_path[:, 1]) - flame_path[:, 1] # y-coordinates in the NED frame, with the origin at the bottom-left (positive up) instead of top-left (positive down) as originally```


2. Next, the the points are recombined into a two-column array:
```powershell
flame_points_x = flame_path[:,0] # x-coordinates in the NED frame
flame_path = np.column_stack((flame_points_x, flame_points_y))  # Combine x and y coordinates into a single array again
```


3. Moreover, it would be convenient if the points started at the coordinate [0;0] for future path planning purposes:

```powershell
# Shift the flame path to start from (0,0)
flame_path[:, 0] = flame_path[:, 0] - flame_path[0][0] # Normalize to start from (0,:)
flame_path[:, 1] = flame_path[:, 1] - flame_path[0][1] # Normalize to start from (:,0)
```



4. And finally, the size of the flame path should be reduced to about a size of 10x10m from its current size of about 1200x1200 (which is the extent of the imported coordinates from Gimp, corresponding to the pixel locations of each of the points). This is done by the following scaling function:

```powershell
# Scale the flame path to fit in the frame of the world (10mx10m instead of 1200m)
flame_path = flame_path / np.max(flame_path)  # Scale down to fit in the local frame by scaling everything to 0-1 range
flame_path = flame_path * 10.0  # Scale the maximum dimension of the flame to 10m for the trajectory

self.flame_path = flame_path  # Store the flame path for later use
```

The size of the overall path can then be changed in the future by changing the scaling factor in the last line of the provided code. And the adjusted path is then saved to the drones for later use.

The saved path can then be used in a straightforward manner for flying in the xy-plane in the leader local frame. For the two follower drones, the coordinate transformation described in the wiki entry of 2.A will have to be implemented by calculating the difference between the reference locations of the drone local frames. The implementation of the path to the custom Gazebo world will be described in a later entry of the wiki.
